# Callback Business Rules — Бізнес-логіка та поведінка екранів

> Нотатки з бізнес-логіки, специфічної поведінки та деталей реалізації.
> Дивись цей файл перед імплементацією екранів.

## Feed Module — поведінка (оновлено)

**Нові правила:**
- Геолокація користувача — nullable в `users.location` (додати колонку)
- **Немає обмеження за радіусом** — радіус прибрано
- Користувачу пропонується додати геолокацію для ранжування за відстанню
- Відстань до поста виводиться: `"📍 2.3 км від вас"`

**Сортування:**
1. Якщо є геолокація: за відстанню (найближчі перші)
2. Якщо немає геолокації: за датою (новіші перші)

---

## Нотатки

### 1. Специфічна логіка екранів

#### PET_UPDATE (Оновити анкету)
- Кнопка **НЕ з'являється** якщо тварина має нестандартний статус:
  - На перетримці
  - В процесі пошуку
  - Є заява на адопцію/перетримку

#### FEED_GEOLOCATION (Обрати геолокацію для стрічки)
- Показує поточну геолокацію користувача (якщо є)
- Користувач надсилає нову геолокацію
- Зберігається в users.location
- **Нове повідомлення** (Telegram не дозволяє редагувати геолокацію)

#### SEARCH_FOUND (Я знайшов тварину)
- **Геолокація обов'язкова** при створенні анкети знахідки

#### ADOPTION_GET → Фільтр
- Тимчасово не працює, буде реалізовано в кінці проєкту

---

### 2. Поведінка повідомлень (History Mode)

Деякі екрани виводять **нові повідомлення** замість оновлення існуючих:

| Екран | Поведінка |
|--------|----------|
| FEED_VIEW (Перегляд оголошення) | Кожне оголошення = нове повідомлення |
| SEARCH_FOUND_MATCHES (Перегляд потенційних збігів) | Кожна анкета = нове повідомлення |
| SEARCH_RECOMMENDATIONS (Переглянути рекомендації) | Кожна рекомендація = нове повідомлення |
| ADOPTION_GET (Отримати тварину) | Кожна тварина = нове повідомлення |

**Натискання "Повернутись"** в цих екранах:
- Відправляє **нове повідомлення** з меню (parent)
- Далі логіка стандартна — редагування повідомлення

## Feed Module — Functional Requirements

| ID | Description |
|----|------------|
| FR-1 | Користувач може додати публікацію: текст + фото + геолокація |
| FR-2 | Користувач може переглянути стрічку оголошень |
| FR-3 | Користувач може встановити/змінити свою геолокацію |
| FR-4 | При перегляді показується відстань до поста ("📍 2.3 км від вас") |
| FR-5 | При налаштованій геолокації пости сортуються за відстанню |
| FR-6 | Без геолокації — сортування за датою |
| FR-7 | При пагінації пропускаються вже переглянуті публікації |
| FR-8 | Користувач може переглянути свої публікації |
| FR-9 | Користувач може видалити свою публікацію |

---

### 3. Пагінація

#### SEARCH_FOUND_MATCHES (Перегляд потенційних збігів)
- Показуються **тільки анкети з контактною інформацією**
- Анкети без контактів не виводяться (вони марні)

#### Сортування в ADOPTION_RESPONSE_DETAIL (відгуки)
Відгуки сортуються:
1. **Спочатку за статусом** (підтверджені → нові → відхилені)
2. **Потім за датою**

---

### 4. Статуси відгуків (смайлики)

| Статус | Смайлик | Опис |
|--------|---------|------|
| Новий відгук/оголошення | 🆕 | Очікує на розгляд |
| Відхилений відгук | ❌ | Відхилено власником |
| Підтверджений (чекає фіналу) | ⏳ | Власник підтвердив, очікує фінальне підтвердження від охочого |

---

### 5. Перетримка (Foster)

Логіка **повністю дублює Адопцію**, але з відмінностями:

| Поле | Адопція | Перетримка |
|-------|--------|-----------|
| Статус тварини | Передача | На перетримці |
| Тимчасовий власник | ❌ | user_id перетримувача |
| Автоматичне повернення | ❌ | Так (після закінчення тривалості) |

**Після фінального підтвердження:**
1. Статус тварини → "На перетримці"
2. Поле `тимчасовий_власник` = user_id
3. Поле `тривалість` = вказана користувачем
4. Після закінчення тривалості → автоматично повертається у стандартний статус

---

### 6. Форми (Step-by-Step)

Деякі екрани ініціюють **поетапне заповнення форми**:

#### SEARCH_START (Почати пошук)
1. Обрати тварину
2. Обрати геолокацію
3. Вказати характерні ознаки (опціонально)
4. Вказати контактну інформацію (опціонально)
5. Фінальне підтвердження

#### SEARCH_FOUND (Я знайшов тварину)
1. Додати фото (**обов'язково**)
2. Заповнити повну анкету
3. Додати геолокацію
4. Додати характерні ознаки (опціонально)
5. Я завершив → Перегляд потенційних збігів

#### ADOPTION_GIVE (Віддати тварину)
1. Обрати тварину
2. Додати коментар
3. Підтвердити / Очистити

**Поведінка кнопки "Очистити":**
- Очищує всі введені дані
- Починає заповнення з початку

---

### 7. Логіка підтвердження

#### ADOPTION_RESPONSE_DETAIL → Фінальне підтвердження
Кнопка "Підтвердити" (фінальне) з'являється **тільки** коли власник вже підтвердив відгук.

#### ADOPTION_RESPONSE_DETAIL (власник)
- Можна підтвердити **тільки один** відгук на одну тварину
- Відхилення не видаляє відгук, змінює статус
- Відхилені відгуки можна **відновити**

---

### 8. Видалення

#### PET_DELETE_CONFIRM
- Підтвердження → видаляє анкету тварини
- Тварина повертається у звичайний статус

#### FEED_POST_DELETE_CONFIRM
- Підтвердження → видаляє оголошення

#### ADOPTION_POST_DELETE_CONFIRM
- Підтвердження → видаляє оголошення про передачу

---

### 9. Геолокація

#### SEARCH_CLAIM_PET (Це моя тварина)
- Якщо геолокації на анкеті знахідки **немає**:
  - Кнопка "Це моя тварина" **не показується**
  - Або показується, але при натисканні виводиться повідомлення "Геолокацію не додано"
- **Рішення:** Геолокація обов'язкова → кнопка завжди показується

---

### 10. Контактна інформація

При заповненні форми "Почати пошук" (Lost):
- Користувачу пояснюється: **якщо надати контактну інформацію, той хто знайде тварину зможе зв'язатись**

При перегляді потенційних збігів (той, хто знайшов):
- Виводяться контактні дані власника
- Користувач може зв'язатись з власником

---

### 11. Нотатки

- Всі підтвердження/відхилення мають кнопку "Повернутись"
- "Наступний пост/анкета/тварина" — при пагінації
- Смайлики в списках тварин:
  - 🏠 — на перетримці
  - 🔍 — в процесі пошуку
  - 🎯 — шукає перетримку/господаря
