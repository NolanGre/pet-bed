# Feed Module Analysis

## Overview

Модуль **Feed** (стрічка оголошень) — публікації користувачів з можливістю фільтрації за геолокацією.

---

## Business Logic Rules

### Rights & Access

| Rule | Description |
|------|-------------|
| R-1 | Тільки **волонтер** може додавати пости |
| R-2 | Кнопка **"Створити пост"** показується тільки волонтерам |
| R-3 | Кнопка **"Мої пости"** показується тільки волонтерам з **>1 постом** |
| R-4 | При зміні типу акаунту на **REGULAR** — пости **видаляються** + інформується користувач |

### Post Content

| Rule | Description |
|------|-------------|
| R-5 | Пост містить: **фото + текст + відстань** |
| R-6 | Відстань **< 1 км** — виводиться в **метрах** (напр. "📍 500м від вас") |
| R-7 | Відстань **>= 1 км** — виводиться в **кілометрах** (напр. "📍 2.3 км від вас") |
| R-8 | Якщо геолокація користувача **не встановлена** — відстань **не показується** |

### Navigation

| Rule | Description |
|------|-------------|
| R-9 | Кнопки навігації: **"Наступний"**, **"Повернутись"** |
| R-10 | При натисканні **будь-якої** кнопки — **прибирається клавіатура** (editMessage з reply_markup = null) |
| R-11 | **"Повернутись"** → повертає до меню Постів |
| R-12 | **"Наступний"** → отримує наступний актуальний пост з БД (не пагінація) |

### Sorting

| Rule | Description |
|------|-------------|
| R-13 | Якщо є геолокація: сортування за відстанню (найближчий → найдальший) |
| R-14 | Якщо немає геолокації: сортування за датою (новіші перші) |

### User Actions

| Rule | Description |
|------|-------------|
| R-15 | Перегляд поста — він додається в історію переглядів |
| R-16 | При запиті наступного поста виключаються вже переглянуті пости |

## User Stories

### US-1: Перегляд стрічки
> Як користувач, щоб знайти цікаві оголошення, я хочу переглядати стрічку публікацій.

**Scenario:**
1. Користувач відкриває меню → натискає "Стрічка"
2. Якщо геолокація не встановлена:
   - Сортування за датою (новіші перші)
   - Показується: *"Додайте геолокацію для ранжування за відстанню"*
3. Якщо геолокація встановлена:
   - Перші: нові публікації від волонтерів (незалежно від відстані)
   - Далі: всі інші, від найближчого до найдальшого
4. Кожен пост показує відстань: "📍 2.3 км від вас"

### US-2: Налаштування геолокації
> Як користувач, щоб отримувати релевантні оголошення поблизу, я хочу вказати свою геолокацію.

**Scenario:**
1. Користувач натискає "Геолокація" в меню стрічки
2. Бот пропонує надіслати геолокацію
3. Користувач надсилає геолокацію
4. Геолокація зберігається в профілі користувача

### US-3: Створення публікації
> Як волонтер, щоб поділитися інформацією, я хочу створити публікацію.

**Scenario:**
1. Волонтер натискає "Створити публікацію"
2. Заповнює форму:
   - Текст повідомлення (обов'язково)
   - Фото (обов'язково)
   - Геолокація (обов'язково)
3. Підтверджує створення
4. Публікація з'являється в стрічці (першою для всіх волонтерів)

### US-4: Перегляд моїх публікацій
> Як волонтер, щоб керувати своїм контентом, я хочу переглядати свої публікації.

**Scenario:**
1. Волонтер натискає "Мої публікації" (тільки якщо > 1 поста)
2. Показується список власних публікацій
3. Можна переглянути деталі або видалити

## Database Schema

### users (оновлено)

| Колонка | Тип | Опис |
|---------|-----|------|
| ... | ... | ... |
| location | GEOGRAPHY(POINT, 4326) | Геолокація користувача (nullable) |

### feed_posts

| Колонка | Тип | Опис |
|---------|-----|------|
| id | BIGINT | PK |

| location | GEOGRAPHY(POINT, 4326) | Геолокація (PostGIS) |

| updated_at | TIMESTAMP | Дата оновлення |

### users_feed_history

| Колонка | Тип | Опис |
|---------|-----|------|
| user_id | BIGINT | PKPart → users(id), хто переглянув |
| post_id | BIGINT | PKPart → feed_posts(id), яку публікацію |

## Callback Hierarchy

```
FEED_MENU
├── FEED_VIEW (перегляд стрічки)
├── FEED_GEOLOCATION (обрати геолокацію)
├── FEED_MY_POSTS (мої публікації) — тільки волонтери з >1 постом
├── FEED_CREATE (створити публікацію) — тільки волонтери
└── FEED_POST_DETAIL
    └── FEED_POST_DELETE_CONFIRM (підтвердження видалення)
```

---

## Key Rules Summary

- Геолокація користувача — nullable в `users.location`
- Відстань рахується через PostGIS `ST_Distance`
- Волонтери завжди перші (ORDER BY created_at DESC)
- При зміні типу на REGULAR — пости видаляються

## Required Test Cases

### TC-1: Перевірка сортування — за відстанню

> Пости сортуються від найближчого до найдальшого.

**Setup:**
- Користувач має геолокацію: (50.0, 30.0)
- Існує пост А на відстані 5км
- Існує пост Б на відстані 50км

**Expected:**
- Першим показується пост А (найближчий)
- Другим — пост Б

### TC-2: Правильний розрахунок відстані

> Відстань рахується коректно.

**Setup:**
- Геолокація користувача: (50.0, 30.0)
- Геолокація поста: (50.01, 30.01) — приблизно 1.57 км

**Expected:**
- Відстань показується як "📍 1.6 км від вас"
- **Примітка:** Значення можуть відрізнятись — уточнити після реалізації

### TC-3: Відстань менше 1 км — в метрах

> Якщо відстань менша за 1км, виводиться в метрах.

**Setup:**
- Геолокація користувача: (50.0, 30.0)
- Геолокація поста: (50.005, 30.005) — приблизно 700м

**Expected:**
- Відстань показується як "📍 700м від вас"
- **Примітка:** Значення можуть відрізнятись — уточнити після реалізації

### TC-4: Видалення постів при зміні типу акаунту

> Коли волонтер змінює тип на REGULAR, його пости видаляються.

**Setup:**
- Користувач є волонтером з 2 постами
- Користувач натискає "Змінити тип акаунту" → обирає REGULAR

**Expected:**
- Всі пости користувача видаляються
- Користувачу показується повідомлення: *"Ваші публікації видалено"*

### TC-5: Видалення клавіатури при навігації

> Коли користувач натискає будь-яку кнопку навігації, клавіатура прибирається.

**Setup:**
- Користувач переглядає пост з клавіатурою (кнопки "Наступний", "Повернутись")

**Action:** Натискає "Наступний"

**Expected:**
- Редагується повідомлення з reply_markup = null
- Клавіатура більше не відображається

### TC-6: Наступний пост — отримання одного поста з БД

> При натисканні "Наступний" — запит до БД, bukan пагінація.

**Setup:**
- Користувач переглянув пост 1
- В БД є ще пости 2, 3, 4

**Action:** Натискає "Наступний"

**Expected:**
- Система робить запит до БД
- Отримує один наступний пост (сортування + виключення переглянутих)
- Пост 2 додається в історію переглядів

### TC-7: Пропуск переглянутих постів

> Вже переглянуті пости не показуються.

**Setup:**
- Користувач переглянув пости 1, 2
- В БД є пости 1, 2, 3, 4

**Action:** Натискає "Наступний"

**Expected:**
- Показується пост 3 (1 і 2 вже переглянуті)

### TC-8: Кнопка "Мої пости" тільки для волонтерів з >1 постом

> Кнопка показується тільки якщо >1 пост.

**Setup:**
- Волонтер має 1 пост
- Волонтер має 2 пости

**Expected:**
- З 1 постом — кнопка НЕ показується
- З 2 постами — кнопка показується

### TC-9: Кнопка "Створити пост" тільки для волонтерів

> Кнопка показується тільки волонтерам.

**Setup:**
- Користувач є REGULAR
- Користувач є VOLUNTEER

**Expected:**
- REGULAR — кнопка НЕ показується
- VOLUNTEER — кнопка показується
